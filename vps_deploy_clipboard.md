# Инструкция по деплою проекта "Clipboard" на VPS (Aeza)

**Целевой сервер:** VPS-2 (Aeza)
**IP адрес:** `109.120.134.188`
**Пользователь SSH:** `admin` (авторизация по ключу `~/.ssh/id_ed25519` с Gamebox)
**OS:** Ubuntu 24.04 LTS
**Ресурсы:** 1 Core, 4 GB RAM, 10 GB NVMe (ресурсов достаточно для стабильной работы Docker-стека).

## Задача агента
Развернуть проект `dubtab` (фронтенд, бэкенд, БД — в зависимости от архитектуры проекта) в Docker-контейнерах на удаленном VPS. На данном этапе реверс-прокси (Nginx/Traefik) и домены **не используются**. Доступ должен осуществляться напрямую по IP и порту (`http://109.120.134.188:PORT`).

## Шаги для деплоя

### 1. Подготовка окружения на VPS
- Подключись к серверу: `ssh -i ~/.ssh/id_ed25519 admin@109.120.134.188`.
- Убедись, что на сервере установлены `docker` и `docker-compose` (или плагин `docker compose`).
- Создай рабочую директорию для проекта, например: `/opt/dubtab` или `/home/admin/dubtab`.

### 2. Перенос кода / Конфигурации
- Скопируй `docker-compose.yml` и необходимые файлы проекта с локальной машины (Gamebox) на VPS (используй `scp` или `rsync`). Если проект лежит в Git-репозитории, склонируй его прямо на VPS.
- Проверь переменные окружения (`.env` файлы). Убедись, что фронтенд знает, на каком IP:PORT стучаться к бэкенду (вместо `localhost` там должен быть публичный IP сервера `109.120.134.188` или корректная маршрутизация внутри Docker-сети).

### 3. Настройка Firewall (UFW)
- По умолчанию на сервере настроен строгий UFW (`deny incoming`).
- Узнай, на каких портах крутятся внешние сервисы `dubtab` (например, 8080 для фронта, 3000 для бэкенда).
- Разреши эти порты в UFW:
  ```bash
  sudo ufw allow <PORT>/tcp
  sudo ufw reload
  ```

### 4. Запуск и проверка
- Запусти стек:
  ```bash
  docker compose up -d --build
  ```
- Проверь логи на наличие ошибок:
  ```bash
  docker compose logs -f
  ```
- Убедись, что контейнеры поднялись и не падают (`docker ps`).
- Проверь доступность снаружи: попробуй сделать HTTP-запрос (curl или браузер) на `http://109.120.134.188:<PORT>`.

## Важные примечания для агента
- **Безопасность:** Не открывай в UFW порты баз данных (PostgreSQL/Redis и т.д.), они должны общаться с бэкендом только внутри закрытой Docker-сети. Наружу торчат только фронтенд и, при необходимости, публичное API бэкенда.
- **Отказоустойчивость:** Убедись, что в `docker-compose.yml` для всех сервисов проставлен `restart: always` или `restart: unless-stopped`.
