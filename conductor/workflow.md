# Протокол рабочего процесса Conductor

## Стандарты тестирования
- Каждая новая функция должна сопровождаться тестами.
- Требуемое покрытие тестами: >80%.
- Перед переходом к следующей задаче необходимо запустить существующие тесты, чтобы убедиться в отсутствии регрессий.

## Управление версиями (Git)
- **Частота коммитов:** Коммит после каждой выполненной подзадачи.
- **Сообщения коммитов:** Четкие и краткие описания внесенных изменений.
- **Резюме задач:** Краткое резюме выполненной работы должно быть включено в тело сообщения коммита.

## Фазы реализации
1. **Планирование:** Определение спецификации и плана реализации.
2. **Разработка:** Выполнение задач по одной.
3. **Верификация:** Проверка корректности изменений с помощью тестов и ручного тестирования.
4. **Завершение:** Финальная проверка и отметка задачи как выполненной.

## Протокол верификации завершения фазы
Для каждой фазы в плане реализации должен быть выполнен финальный мета-таск:
- `Conductor - User Manual Verification '<Phase Name>' (Protocol in workflow.md)`
Этот таск подтверждает, что все цели фазы достигнуты и изменения соответствуют стандартам качества.
