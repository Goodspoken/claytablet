# Критический Аудит и План Улучшений (Docker, Security, UX)

Я провел критический аудит архитектуры, Docker-конфигурации и кодовой базы. Ниже представлены найденные уязвимости, узкие места и план по их устранению.

## 1. Уязвимости и Баги (Security & Bugs)

### 🔴 Уязвимость: Root в Docker
**Проблема:** Бэкенд-контейнер работает от пользователя `root`. При монтировании volume (`./data:/app/data`) папка `data` на хост-машине получает права root, что может вызывать ошибки прав доступа у пользователя (например, при локальном запуске).
**Решение:** Добавить `USER` в `Dockerfile` (например, встроенного `nobody` или создать пользователя `appuser`).

### 🔴 Уязвимость: Stored XSS через SVG
**Проблема:** В `ALLOWED_EXTENSIONS` разрешен `.svg`. Эндпоинт `/api/files/{filename}` отдает его напрямую. Злоумышленник может загрузить SVG с зашитым JavaScript, который выполнится при открытии файла в браузере в контексте домена `claytablet.online`.
**Решение:** Для всех загружаемых файлов (кроме строго безопасных картинок) нужно принудительно ставить заголовок `Content-Disposition: attachment` (скачивание, а не открытие в браузере) или очищать SVG на бэкенде. Если раздавать через Caddy, можно настроить заголовки там.

### 🟡 Баг/Недочет: Отсутствие Healthcheck для Frontend
**Проблема:** В `docker-compose.yml` есть healthcheck для бэкенда, но нет для фронтенда (Caddy). Докер не узнает, если веб-сервер упадет.
**Решение:** Добавить `healthcheck: wget --no-verbose --tries=1 --spider http://localhost/ || exit 1` в сервис frontend.

## 2. Оптимизация производительности (Performance)

### 🚀 Раздача статики через Caddy (вместо Python)
**Проблема:** Сейчас файлы из папки `data/media` читаются с диска питоном и отправляются через FastAPI. Python медленный в I/O операциях по сравнению с веб-серверами.
**Решение:** В `docker-compose.yml` прокинуть volume `data` также и в frontend-контейнер. В `Caddyfile` добавить правило: запросы к `/api/files/*` отдавать напрямую с диска.

### 🚀 Production-ready сервер (Gunicorn/Uvicorn Workers)
**Проблема:** В `Dockerfile` бэкенда используется `CMD ["uvicorn", "main:app"]`. Это запускает всего 1 воркер (1 процесс). Он использует только 1 ядро процессора.
**Решение:** Изменить запуск на `fastapi run` (в новых версиях FastAPI) или `uvicorn --workers 4`.

## 3. Удобство для пользователя (UX & DX)

### 🤖 Автоматическое подтягивание конфигов (Config Endpoint)
**Проблема:** На фронтенде сейчас жестко зашиты лимиты (50 МБ размер файла, список доступных форматов). Если мы поменяем это на бэкенде, фронтенд не узнает.
**Решение:** Создать эндпоинт `GET /api/config` (выдает `max_file_size`, `allowed_extensions`, `ttl_presets`). Фронтенд при старте забирает этот конфиг и адаптирует UI (например, показывает пользователю: "Макс. размер файла: 50 МБ").

### 🟢 Индикатор соединения (Connection Status)
**Проблема:** Если WebSocket отключается (моргнул интернет), пользователь может не понять, почему файлы не появляются, пока не обновит страницу.
**Решение:** Добавить маленький индикатор статуса (Зеленая точка = Подключено, Желтая = Переподключение, Красная = Отключено).
