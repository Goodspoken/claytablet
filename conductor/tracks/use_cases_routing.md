# Трек: Профили использования (Use Cases) и Роутинг сценариев

**Целевое видение:** PopyCast должен адаптироваться под разные потребности пользователей, предоставляя соответствующий UX для каждого из базовых сценариев.

## Основные профили (Сценарии):

1. **"Локальная синхра" (Personal Sync):**
   - *Цель:* Быстро перекинуть ссылку, фото или текст между своим телефоном и компьютером.
   - *Фичи:* Device Pairing (одна общая доска без явных ссылок-приглашений), автосинхронизация буфера обмена (Background clipboard sync на десктопе/мобилке).

2. **"Коллаборация с друзьями" (Remote Collaboration):**
   - *Цель:* Иметь общую доску с друзьями по интернету для проекта, игры или мозгового штурма.
   - *Фичи:* Временные комнаты по ссылке, защита паролем, разделение экрана (Canvas + чат), индикаторы присутствия (кто онлайн, кто печатает).

3. **"Записная книжка для AI" (LLM Scratchpad / Context Buffer):**
   - *Цель:* Удобное место для сбора промптов, кода и ссылок при работе с нейросетями, либо напрямую интеграция с локальными AI.
   - *Фичи:* Model Context Protocol (MCP) интеграция — чтобы локальный агент (например, Antigravity) мог делать запросы типа "прочитай буфер PopyCast", "отправь этот файл на доску PopyCast". Генерация Markdown-конспекта из текущей доски. Моментальное копирование кода в 1 клик.

4. **"Публичные доски" (Public Bulletin Boards):**
   - *Цель:* Открытые комнаты для сообществ (на будущее).
   - *Фичи:* Режим Read-Only для гостей, модерация, закрепленные посты, защита от флуда/спама.

## Что это значит для разработки:
При старте на главной странице можно предлагать "Быстрые сценарии": 
- [Создать временную комнату] 
- [Подключить мое устройство] 
- [Открыть рабочую область AI].
Архитектура бэкенда должна позволять четко разделять права доступа (владелец, редактор, читатель, API-агент) для каждого типа комнат.
