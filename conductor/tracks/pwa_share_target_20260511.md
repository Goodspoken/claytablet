**Статус:** ✅ Завершён

**Дата создания:** 2026-05-11  
**Задеплоено:** 2026-05-11 на dubtab.app

## Цель

Сделать так, чтобы DubTab появлялся в системном меню «Поделиться» на Android/iOS — так же как Google Drive, Nextcloud, Telegram. Пользователь нажимает «Поделиться» в галерее → выбирает DubTab → фото/файл/текст улетает в нужную комнату.

---

## Что сделано ✅

### Service Worker (`public/sw.js`)
- Перехватывает POST-запрос на `/share` от ОС (Web Share Target API)
- Читает multipart/form-data: поля `title`, `text`, `url` и массив `files`
- Сохраняет метаданные и файлы во временный Cache API с уникальным ключом
- Редиректит браузер на `/share?key=<key>` (303 Found)

### Manifest (`public/manifest.json`)
- Добавлен блок `share_target` с `method: POST`, `enctype: multipart/form-data`
- Принимает: `image/*`, `audio/*`, `video/*`, `application/*`, `*/*`
- Параметры: `title`, `text`, `url`, `files`

### Страница шаринга (`src/pages/SharePage.tsx`)
- Читает метаданные и файлы из Cache API через service worker
- Показывает превью: миниатюры изображений, имена файлов, текст/ссылку
- Список последних 8 комнат из `localStorage['recentRooms']` — одно нажатие для отправки
- Поле ввода для ручного ввода ID комнаты
- После отправки — авторедирект на комнату через 1.2 секунды
- Поддерживает: изображения (`addImage`), аудио (`addAudio`), файлы (`addFile`), текст (`addText`)

### Регистрация SW (`src/main.tsx`)
- `navigator.serviceWorker.register('/sw.js')` при загрузке страницы

### Роутинг (`src/App.tsx`)
- Маршрут `/share` → `<SharePage />` добавлен до `/:roomId`

## Как использовать

**Настройка (один раз):**
1. Открыть `dubtab.app` в Chrome на Android
2. Меню браузера → «Добавить на главный экран» (или «Установить приложение»)
3. DubTab теперь зарегистрирован как получатель шаринга

**Использование:**
- Галерея → фото → «Поделиться» → DubTab
- Браузер → ссылка → «Поделиться» → DubTab
- Любой файл → «Поделиться» → DubTab
- Откроется страница с превью + список последних комнат → тап → готово

## Технические детали

- Cache API используется как временное хранилище файлов между POST (SW) и GET (React)
- Ключ кэша: `Date.now().toString(36) + random` — уникален, коллизий нет
- SW регистрируется через `navigator.serviceWorker.register` при load, не блокирует рендер
- `/share` стоит перед `/:roomId` в роутере — иначе `share` воспринимался бы как roomId
